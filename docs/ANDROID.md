# Сегодня идём на Android

Приложение — Kivy-клиент с анимированным фоном и картой Москвы. Android 7.0 и новее, процессор ARM64. Сервер FastAPI работает на компьютере или на отдельном сервере; APK не запускает сервер внутри телефона.

Локальная тестовая версия добавлена в текущие исходники: она открывает готовый аккаунт, шесть мероприятий и офлайн-схему без API и почты. На Windows она запускается через `START_DEMO_WINDOWS.bat`. Опубликованный ниже APK 1.2.0 содержит прежний серверный клиент; нового APK с демо в этом обновлении нет.

## Установка APK

[Скачать APK 1.2.0 напрямую](https://github.com/dhdhsbdbd132-sys/ssdsad/releases/download/v1.2.0/todaygo-1.2.0-arm64-v8a-debug.apk). Архив распаковывать не нужно: откройте файл на телефоне. При установке разрешите вашему браузеру установку этого приложения. Это debug-сборка для проверки проекта, без публикации в Google Play. [Страница релиза и контрольные файлы](https://github.com/dhdhsbdbd132-sys/ssdsad/releases/tag/v1.2.0).

Параметры подключения сохраняются в приватном каталоге приложения. Пароли и токены на диске не сохраняются. При новой CI-сборке debug-подпись может измениться: если Android не позволяет установить обновление поверх предыдущего, удалите старое приложение и установите новый APK. Тогда адрес сервера на телефоне нужно ввести заново; аккаунты и события в базе на компьютере сохранятся.

## Подключение к Windows-компьютеру через Wi-Fi

1. Подключите телефон и компьютер к одной сети Wi-Fi.
2. На компьютере откройте `START_ANDROID_SERVER_WINDOWS.bat`. Оставьте окно сервера открытым. Если Windows спросит о доступе Python к сети, разрешите доступ в вашей частной домашней сети.
3. Скопируйте адрес из окна сервера, например `http://192.168.1.15:8000`.
4. При первом запуске APK откроется экран подключения. Введите адрес компьютера и отметьте «Сервер на моём ПК через Wi-Fi». Нажмите «Проверить и подключиться».
5. Откроется главный экран. Регистрация и вход используют код по почте. Для реальной отправки настройте Mail.ru на компьютере через `CONFIGURE_EMAIL_WINDOWS.bat`.

`localhost` и `127.0.0.1` на телефоне означают сам телефон. Адрес компьютера может измениться после переподключения к Wi-Fi; изменить его можно через экран подключения в профиле. Если смартфон находится в гостевой Wi-Fi-сети, маршрутизатор может запрещать связь с компьютером.

HTTP разрешается в клиенте только после вашего явного выбора и только для адресов частной сети `10.x.x.x`, `172.16.x.x`–`172.31.x.x` и `192.168.x.x`. Для сервера в интернете используйте HTTPS. Секреты SMTP и пароль приложения Mail.ru остаются на сервере и в APK не попадают.

## Проверка установленного приложения

- После запуска видны движущийся фон и карта Москвы.
- На экране подключения проверяется доступность `/api/health` до сохранения адреса.
- Откройте список событий, запись, регистрацию и экран ввода почтового кода.
- Создайте, измените и удалите запись под аккаунтом организатора.
- Проверьте возврат кнопкой Android «Назад», выход и повторный запуск.

На телефоне требуется интернет для онлайн-карты; при недоступных тайлах доступна схема Москвы. Разрешения на местоположение и общий доступ к файлам не запрашиваются. Точку события можно выбрать вручную на карте.

## Повторная сборка через GitHub Actions

Откройте Actions → **Android debug APK** → **Run workflow**. При успешной сборке артефакт `todaygo-debug-apk` содержит APK, `SHA256SUMS.txt` и `BUILD.txt` с исходным commit. Отдельный файл SHA256 позволяет проверить целостность скачанного APK.

Для повторной публикации проверенного артефакта откройте **Publish verified Android APK** и укажите ID успешного Android run и тег. Публикация 1.2.0 принимает только исправленные сборки из истории `main`, проверяет источник, SHA256, все нативные библиотеки и живой HTTPS карты. Релиз открывается после загрузки всех трёх файлов; существующий опубликованный релиз с другим содержимым не перезаписывается. Для новой версии нужно отдельно обновить номер версии и тег.

Workflow использует Ubuntu 22.04, Python 3.12 для сборочных инструментов, OpenJDK 17, Buildozer 1.6.0, python-for-android v2026.05.09 (commit `58d21141f17c889bf8585f5665921d72028f8831`) и NDK 28c. Внутри APK используется Python 3.12.14 и Kivy 2.3.1; hostpython зафиксирован на ту же версию. Target API — 35, min API — 24, ABI — `arm64-v8a`.

Локальный рецепт Python сохраняет совместимость с Android 7: исключает необязательный Unix-модуль `grp`, который в CPython3.12 без проверки вызывает функции перечисления групп, доступные Android только с API26. Приложение этот модуль не использует. Остальная сборка и патчи используются из зафиксированного upstream-рецепта. SDK, NDK и результаты компиляции кэшируются также после неудачной сборки, чтобы повтор не скачивал весь toolchain заново.

`scripts/build_android.py` использует чистую Python-реализацию `charset-normalizer`; необязательный mypy-ускоритель отключён для сборки из исходников. Также допустим универсальный wheel `py3-none-any` из resolver. `chardet` зафиксирован на чистой Python-версии 5.2.0. Так Linux-расширения зависимостей не попадают в Android-пакет.

Перед загрузкой APK автоматическая проверка читает структуру ZIP и пакета приложения, проверяет архитектуру всех native-библиотек и расширений внутри Python bundle, отсутствие GNU/Linux-зависимостей и GLIBC-версий, русский шрифт, новые модули анимации, package/version/API/INTERNET и цифровую debug-подпись через `apksigner`. Дополнительно проверяются requests, mapview и CA-сертификаты certifi. Проверка установленного приложения на физическом телефоне выполняется отдельно.

## Сборка вручную: Ubuntu 22.04 или WSL2

```bash
sudo apt-get update
sudo apt-get install -y build-essential git zip unzip openjdk-17-jdk autoconf automake libtool \
  pkg-config zlib1g-dev libncurses5-dev libncursesw5-dev libtinfo5 cmake \
  libffi-dev libssl-dev
python3.12 -m venv .android-venv
.android-venv/bin/pip install buildozer==1.6.0 Cython==0.29.37 setuptools==82.0.1
cd client
../.android-venv/bin/python ../scripts/build_android.py
../.android-venv/bin/python ../scripts/verify_android_apk.py bin
```

SDK/NDK скачиваются при первой сборке: нужны интернет и несколько GB свободного диска. APK появится в `client/bin/`. Для 32-битного ARM-устройства можно отдельно изменить `android.archs` на `armeabi-v7a` и собрать другой APK; такой вариант не является основной проверяемой сборкой.

Для production-сборки используйте HTTPS и установите `android:usesCleartextTraffic="false"` в `client/android-application-arguments.xml`. Release-сборку нужно подписать своим ключом. Ключ и keystore нельзя хранить в Git или передавать внутри исходников.
