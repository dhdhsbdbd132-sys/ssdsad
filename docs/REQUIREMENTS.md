# Соответствие заданию

| Требование | Реализация |
|---|---|
| Авторизация / регистрация | Экраны Kivy, пароль + обязательный почтовый код |
| Главный экран | Карта Москвы, категории, поиск, карточки событий |
| Навигация | ScreenManager, нижняя панель, кнопки назад, Android Back |
| Список / просмотр | Афиша с пагинацией и подробная карточка |
| Создание / редактирование | Формы, будущая дата в UTC+3, выбор координат на карте |
| Удаление с подтверждением | Модальное подтверждение, каскадное удаление участия |
| Поиск / фильтрация | Название, описание, адрес, категория, дата, автор, участие |
| Выход | Кнопка в профиле и серверный отзыв сессии |
| FastAPI / полный CRUD | GET список, GET id, POST, PATCH, DELETE |
| JSON и Pydantic | Входные/выходные модели, запрет неизвестных полей |
| Ошибки 400/401/404/500 | Единый обработчик и автоматические проверки |
| Swagger / OpenAPI | `/docs`, `/openapi.json`, схемы и авторизация |
| Все действия Kivy через API | Единственный `ApiClient`, без доступа к БД |
| Реляционная БД | SQLite development, PostgreSQL production, миграции |
| DeclarativeBase / Mapped / mapped_column | `backend/app/core/db.py`, `backend/app/models.py` |
| Session / select / ForeignKey / relationship | ORM-репозитории, связи и каскады |
| CRUD / commit / rollback | Сервисы и зависимость с транзакцией на запрос |
| Разделение архитектуры | UI → HTTP → API → services → repositories → ORM |
| OAuth | OAuth2 endpoint + внешняя Google OIDC/PKCE интеграция |
| Почтовая 2FA | HMAC кода, TTL, лимит попыток, SMTP и development mailbox |
| Сложная ролевая модель | 4 роли, авторство, server-side права, администрирование |
| Refresh token | Хеширование, ротация, TTL, replay detection, logout |
| Защита инфраструктуры | TLS-прокси, rate limits, headers, non-root/read-only Docker |
| Android | Buildozer spec и workflow; APK ещё не собран |

## Из исходных документов

Реализованы UC-01…UC-08: карта, карточка, поиск, присоединение, отмена, создание, редактирование, удаление. Таблицы пользователей, мероприятий и участия соответствуют предложенной модели. Внешняя карта — вспомогательный сервис, backend остаётся единым модульным монолитом.

Из вложений извлечена предметная область и архитектурные требования. Шаблонные указания «вставить оглавление», незаполненные разделы и текст шаблона не трактовались как отдельные команды пользователя.

## Что требует внешней настройки

Настоящая доставка почты — SMTP. Настоящий Google-вход — собственный OAuth client. Детальная онлайн-карта — доступ к OpenStreetMap или резервному HOT / OSM France без ключей; офлайн-схема остаётся доступной без сети. Android APK — запуск сборки и тестирование на устройстве. Production-инфраструктура — развёртывание, DNS, TLS, секреты и резервные копии.
