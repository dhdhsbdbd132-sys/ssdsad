Итого **34 отдельных теста**; 19 серверных дополнительно выполнены на второй СУБД. Клиентские HTTP/UI сценарии запускают отдельный настоящий FastAPI и выполняют регистрацию, почтовую 2FA, создание, открытие по маркеру, участие, редактирование, удаление с подтверждением и выход. Дополнительно проверено сохранение видимой карты и доступных кнопок при размере окна 360 × 700. Девять картографических тестов проверяют повреждённый и устаревший кэш, отказы обоих источников, повторное подключение, реальные текстуры Kivy, сохранение координат/маркеров при переходах и изменении размера окна, отсутствие запросов после закрытия карты. Для воспроизводимости в этих тестах HTTP-тайлы подменены локальными PNG и ошибками транспорта; доставка настоящих улиц проверена отдельно загрузкой и просмотром тайлов обоих провайдеров.

Серверные сценарии: авторские права и модерация, ограничение вместимости, конкурентное обновление ORM, каскады, поиск, валидация, коды 400/401/403/404/409/413/429/500, отсутствие кода в API, лимит/срок OTP, Argon2, logout, refresh rotation/replay, отзыв сессии при смене роли, OpenAPI и OAuth2 endpoint. OIDC проверен с локально подписанным RS256 ID token тестового провайдера и проверкой PKCE; это не фактический вход в Google.

## Повторить

```bash
bash scripts/setup.sh
.venv/bin/pytest backend/tests -q
SDL_VIDEODRIVER=offscreen KIVY_NO_ARGS=1 \
KIVY_HOME="$PWD/.data/kivy" TODAYGO_MAP_MODE=offline \
.client-venv/bin/pytest client/tests -q
```

Для PostgreSQL (нужен Docker):

```bash
bash scripts/run_postgres_tests.sh
```

Скрипт создаёт отдельный контейнер с случайным паролем и свободным локальным портом, запускает тесты/миграции, затем удаляет только этот контейнер и временный файл credentials. Приложение и его БД не удаляются.

Для проверки того же Python-супервизора, который вызывается из `START_WINDOWS.bat`:

```bash
SDL_VIDEODRIVER=offscreen .venv/bin/python scripts/launch_windows.py --smoke-test
```

Проверка открывает настоящий Kivy, получает мероприятия по HTTP, сохраняет снимок в `.data` и закрывает собственный сервер. Дополнительно проверены отказ при одновременном запуске второй копии и доступ к loopback при заданном HTTP-прокси с обеими переменными `NO_PROXY` и `no_proxy`. Windows bootstrap и автоматическая установка Python требуют отдельной проверки на Windows 10/11 x64.

Для Docker без DNS в build worker:

```bash
bash scripts/build_offline_image.sh
```

Пакеты загружаются через штатный HTTPS на хосте и устанавливаются из read-only wheel context; TLS и проверки установки не отключаются. Обычный `deploy/Dockerfile` предназначен для окружения с доступом к PyPI; в этой облачной машине его первая сборка столкнулась с недоступным DNS, после чего проверен `deploy/Dockerfile.offline`.

## Ограничения

- CARTO возвращал HTTP 200 с PNG-заглушкой «API KEY REQUIRED» вместо улиц. Источник заменён на OpenStreetMap с резервным HOT / OSM France: оба проверены на настоящих тайлах Москвы. На компьютере пользователя доступ к внешним источникам зависит от сети; при отказе остаётся схема и кнопка повтора.
- Настоящие SMTP и Google OAuth не проверялись без ваших credentials. В development проверен локальный почтовый mailbox, в тестах — подписанный тестовый OIDC-провайдер. Контейнер проверял только health/read/OpenAPI; указанный в его тестовой конфигурации SMTP-хост — заглушка.
- Android SDK/NDK и APK не собирались. Подготовлены Buildozer config и GitHub Actions; нужна отдельная сборка и проверка на устройстве.
- Nginx/TLS-прокси и публичный сервер здесь не развёрнуты. Hardening контейнера проверен локально; нагрузочный и инфраструктурный аудит не проводился.
- Старлетт выдаёт предупреждение о будущей смене тестового HTTP-клиента; все тесты завершились успешно.

Секреты, локальные почтовые коды, БД и виртуальные окружения исключены из Git. Исходники размещены в GitHub; публикация настроек облачной среды ещё не выполнялась.
