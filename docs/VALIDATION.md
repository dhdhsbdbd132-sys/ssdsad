Итого **131 отдельный тест текущих исходников**: 45 серверных и 86 клиентских; 45 серверных дополнительно выполнены на PostgreSQL 16. Клиентские HTTP/UI сценарии запускают отдельный настоящий FastAPI и выполняют регистрацию, почтовую 2FA, создание, открытие по маркеру, участие, редактирование, удаление с подтверждением и выход. Демо-сценарии запускают настоящий Kivy с полностью запрещёнными HTTP-запросами и локальными данными. Дополнительно проверено сохранение видимой карты и доступных кнопок при размере окна 360 × 700. Девять картографических тестов проверяют повреждённый и устаревший кэш, отказы обоих источников, повторное подключение, реальные текстуры Kivy, сохранение координат/маркеров при переходах и изменении размера окна, отсутствие запросов после закрытия карты. Для воспроизводимости в этих тестах HTTP-тайлы подменены локальными PNG и ошибками транспорта; доставка настоящих улиц проверена отдельно загрузкой и просмотром тайлов обоих провайдеров.

Опубликованный Android APK 1.2.0 относится к исходникам `926dc494`; тестовая версия без сервера добавлена позднее в исходники и не собиралась в новый APK. На опубликованном APK проверены прежние 38 клиентских тестов, а на текущих исходниках — все 86.

Журнал запуска пользователя на Windows выявил конфликт свойства анимации `press` со встроенным событием `ButtonBehavior.on_press`. Регрессионный тест с реальным нажатием воспроизвёл тот же TypeError до исправления. Свойство переименовано в `press_progress`; четыре проверки кнопок и полный клиентский набор прошли в Linux. Основной UI-сценарий теперь удерживает состояние нажатия несколько кадров перед отпусканием, включая регистрацию, CRUD и выход. Исправленная версия на компьютере пользователя ещё не проверена.

После повторного журнала с тем же TypeError проверены публичные исходники и скачанный без авторизации ZIP ветки `main`: оба содержат исправленное свойство. Для обновления уже установленной копии добавлен самостоятельный `REPAIR_WINDOWS.bat`. В официальном PowerShell 7.5 на Linux проверены выбор папки рабочего стола, явной папки и папки рядом с файлом, повторный запуск, уже исправленный файл, отказ для повреждённого/смешанного/неполного исходника и неверного UTF-8, сохранение `on_press`, других классов, BOM/CRLF и точной резервной копии. Контрольные файлы БД, настроек и окружения остались неизменными. Исправленный скриптом исходник старого коммита `403876d` имеет тот же Python AST, что и текущий `theme.py`; его Action и NavAction прошли настоящие pointer down/up с анимацией и без неё. Обёртка CMD, PowerShell 5.1 и замена файла на настоящей Windows-машине здесь не запускались. При нескольких копиях проекта скрипт сначала выбирает `Desktop\ssdsad-main` и показывает путь; нужную папку можно указать перетаскиванием на файл ремонта.

Серверные сценарии: авторские права и модерация, ограничение вместимости, конкурентное обновление ORM, каскады, поиск, валидация, коды 400/401/403/404/409/413/429/500, отсутствие кода в API, лимит/срок OTP, Argon2, logout, refresh rotation/replay, отзыв сессии при смене роли, OpenAPI и OAuth2 endpoint. Google-вход удалён; тест проверяет отсутствие прежних маршрутов в API/OpenAPI. Проверки SSL и STARTTLS используют контролируемый SMTP transport; настоящая доставка Mail.ru требует локальной настройки с паролем внешнего приложения.

## Повторить

```bash
bash scripts/setup.sh
.venv/bin/pytest backend/tests -q
SDL_VIDEODRIVER=offscreen KIVY_NO_ARGS=1 \
KIVY_HOME="$PWD/.data/kivy" TODAYGO_MAP_MODE=offline \
.client-venv/bin/pytest client/tests -q
```

Для PostgreSQL (нужен Docker):

```bash
bash scripts/run_postgres_tests.sh
```

Скрипт создаёт отдельный контейнер с случайным паролем и свободным локальным портом, запускает тесты/миграции, затем удаляет только этот контейнер и временный файл credentials. Приложение и его БД не удаляются.

Для проверки того же Python-супервизора, который вызывается из `START_WINDOWS.bat`:

```bash
SDL_VIDEODRIVER=offscreen .venv/bin/python scripts/launch_windows.py --smoke-test
```

Проверка открывает настоящий Kivy, получает мероприятия по HTTP, сохраняет снимок в `.data` и закрывает собственный сервер. Дополнительно проверены отказ при одновременном запуске второй копии и доступ к loopback при заданном HTTP-прокси с обеими переменными `NO_PROXY` и `no_proxy`. Windows bootstrap и автоматическая установка Python требуют отдельной проверки на Windows 10/11 x64.

Для Docker без DNS в build worker:

```bash
bash scripts/build_offline_image.sh
```

Пакеты загружаются через штатный HTTPS на хосте и устанавливаются из read-only wheel context; TLS и проверки установки не отключаются. Обычный `deploy/Dockerfile` предназначен для окружения с доступом к PyPI; в этой облачной машине его первая сборка столкнулась с недоступным DNS, после чего проверен `deploy/Dockerfile.offline`.

## Ограничения

- CARTO возвращал HTTP 200 с PNG-заглушкой «API KEY REQUIRED» вместо улиц. Источник заменён на OpenStreetMap с резервным HOT / OSM France: оба проверены на настоящих тайлах Москвы. На компьютере пользователя доступ к внешним источникам зависит от сети; при отказе остаётся схема и кнопка повтора.
- Настоящий SMTP не проверялся без учётных данных. Mail.ru настроит локальный мастер; API не публикует пароль или OTP. Контейнер проверял только health/read/OpenAPI; указанный в его тестовой конфигурации SMTP-хост — заглушка.
- Результаты Android-сборки и инструкция установки описаны в [Android](ANDROID.md); установка на физический телефон здесь не выполнялась.
- Nginx/TLS-прокси и публичный сервер здесь не развёрнуты. Hardening контейнера проверен локально; нагрузочный и инфраструктурный аудит не проводился.
- Старлетт выдаёт предупреждение о будущей смене тестового HTTP-клиента; все тесты завершились успешно.

Секреты, локальные почтовые коды, БД и виртуальные окружения исключены из Git. Исходники размещены в GitHub. В настройках облачной среды сохранены актуальные `install_script` и `start_skill`: установка зависимостей, запуск API/Kivy и проверка готовности. Сохранение черновика не публикует среду; изменения применяются после просмотра, сохранения и публикации настроек пользователем.
